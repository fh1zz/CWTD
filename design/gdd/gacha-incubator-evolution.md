# 抽蛋、孵化、部署与进化系统

> v0.2变更：真实用户现要求“扭蛋直接孵出宠物，每宠共5阶段”。本篇保留v0.1原案追溯；当前即抽即用、35阶段数值／技能／图鉴和新增验收以 [v0.2设计](v02-direct-pets-five-stages.md) 为准，旧等待回合规则不再生效。

版本1.0｜Status: Draft｜来源：SRC-I02～I07、I10～I11；EXT-U；EXT-A。未由这些来源规定的补全均为 EXT-D。

## 1. Overview／概述

玩家花局内金币抽取限定编队物种的蛋，等下一符合条件的回合自动孵化，再免费部署到固定地块。三只同种同级宠物可进化为下一阶段；孵化池兼具候补、材料和战术调度用途，10格容量是明确的决策约束。

## 2. Player Fantasy／玩家体验

玩家为下一波提前准备伙伴，在铺开防线与集中进化之间取舍。抽取有随机性，但范围、费用和孵化时点透明；升级产生可见成长，错误操作有即时原因，不能出现扣钱无蛋或宠物凭空消失。

## 3. Detailed Rules／详细规则

### G01：实体与赠送

采用合同 `Pet.Uid/Species/Level/ReadyWave/Pad/Cooldown/IsEgg`。`EXT-D`：Level=1..5用于已孵宠物；ReadyWave>0表示待孵蛋，成功孵化后ReadyWave归0，Level设1。池内Pad=-1；战场Pad为0..13。蛋不参与升级等级排序；其占位Level可初始化1但不能据此当作已孵宠物。

每次成功创建新局或重试，按实际队伍顺序向池赠送前 min(3,M) 种各1只已孵化1级宠物，Cooldown=0，不扣金币，之后执行池排序。满队伍送3只，1或2只队伍只送对应数量；不补入队伍外物种。赠送每个战局一次，不能通过开关UI重复领取。

### G02：抽蛋事务

`SRC-I04 + EXT-U`：Coins≥drawCost且Pool.Count<poolCapacity时可成功抽取；首版drawCost=50、poolCapacity=10。只从本局实际队伍均匀独立抽取，无保底、权重、付费货币和场外抽卡。概率在扭蛋区可见。抽取时确定Species并保存，孵化不再重抽；蛋外观可暂不揭示物种，用户始终知道只来自当前队伍。

每次DrawEgg先校验阶段和暂停，再校验金币，再校验容量和合法队伍；同时缺钱且满池时先提示缺钱。所有条件满足后，扣金币、推进一次随机抽取、创建唯一Uid蛋并入池一次性提交。失败不扣款、不推进抽取随机流、不改队伍或实例。响应包含中文LastMessage，失败原因由HUD统一显示2秒且期间不重复。

灰态并不取消解释能力：点击灰按钮由UI根据当前状态解释，不能以GUI完全不可点击而失去原因提示。扭蛋机收起仅改变展示，可展开恢复；抽取成功逻辑不等待视觉动画结束，也不因动画取消回滚。防止一次按下／抬起被计作两次DrawEgg。

### G03：回合孵化

严格使用合同：Wave=0时购蛋，ReadyWave=2；Wave=N≥1时，无论Running还是清波后的Preparing，购蛋ReadyWave=N+1。只有成功StartWave后先将Wave加1，再自动孵化ReadyWave≤新Wave的蛋，原Uid保留，ReadyWave归0，显示破壳表现，随后统一排序。

示例：初始准备Wave0买蛋→开第1波仍为蛋→第1波结束处于Preparing/Wave1仍为蛋→手动开第2波瞬间变宠物。第2波准备期指“第1波结束、尚未开第2波”，其内部Wave仍1；UI必须同时显示“已完成1/总波数，下一波2”，不能让名称混淆影响ReadyWave。

`SRC-I06` 的“过1个回合自动孵化”由上述时点落地；自动发生无需领取。池满不妨碍原槽孵化，因为蛋变宠物不增加总数。关闭孵化池不阻止孵化。

最后一波进行中仍满足金币／容量时允许抽蛋，遵守原案抽取条件；蛋ReadyWave=总波数+1，显示“本局无下一回合，无法孵化”。不会清场自动孵化、额外开隐藏波或退款；不会把蛋带出局。扭蛋区在末波保持该风险文字，单次提示仍遵守2秒规则。末波结束战局锁定，不再允许抽蛋。

### G04：池与排序

池默认10格，蛋和宠物都各占1格。排序键：先宠物后蛋；宠物按Level降序→元素金、木、水、火、土、光、暗→Uid升序；蛋按Uid升序，不能按未知物种让蛋提前。部署、孵化、进化必须触发排序；`EXT-D` 抽取、出售、回收后也重排以维持同一不变量。选中引用使用Uid，不使用排序前格子下标。

池和扭蛋机各自可以收起展开，展开状态独立，具有过渡动效；池收起时相关进化／出售／宠物信息一起收起。数据、容量、孵化和战场战斗不受收起影响。

### G05：部署、回收、出售

首版14个固定Pad，免费部署已孵宠物。点击池宠物再点击空Pad完成；UI展示合法地块和范围预览。非法区域、占用Pad、蛋、失效Uid、暂停或结束均拒绝，原宠物留在原处。点击空白取消尚未提交的部署选择，不占位；成功操作从Pool移到Towers，同一Uid只存在一个容器。首版不开放地图自由摆放或塔直接拖到另一Pad。

回收Recall：选中战场宠物→点击“回收至池”；池空位足够才从Towers移入Pool、Pad=-1，保持Species、Level、Uid、剩余Cooldown，不退金币。池满拒绝，不临时删除塔腾空。调整位置需要回收后重新部署，不能用回收按钮代替出售。`EXT-D` 池内CD在Preparing冻结、Running随模拟时间递减；重新部署保留该CD，不凭空刷新攻击。新赠宠物和新孵宠物CD=0，首次合法部署可在下一个有效Tick攻击。

出售Sell：池中或战场的已孵宠物可以出售，成功增加SellValue并删除该实例；蛋不可出售，也不可部署、进化或“丢弃”。按钮显示当前返还金额，点击一次立即提交；不另加确认弹窗。冷却、选择和支援关系随移除刷新，已生效的伤害不撤销。回收、部署、出售成功后清理涉及对象的旧面板；失败保留当前合法选择。

### G06：池内批量进化

`SRC-I10～I11`：只考虑池内已孵、Level<maxLevel、Species和Level均相同的宠物，三个一组。只要任意组足够3只就显示池全局【进化】按钮；选中蛋仍可看到池自身的批量进化入口，但蛋不参与且无单体信息面板。

一次点击建立池快照，以(Species,Level)分组、组内Uid升序。每组取floor(数量/3)个三元组，全部组在一次事务内各升1级；不足3的余数不变。产物不能再次进入本次快照。`EXT-D` 每组三只中保留最小Uid为产物主体，其Level加1、Cooldown取主体当前值与新interval较小值，另两只删除。此处不从战场拿材料。

9只1级火狐→3只2级火狐，不能一键变1只3级；下一次点击才允许3只2级变1只3级。同次快照中原本已有3只2级，允许它们自己的组变3级，但不能把本次刚生成2级加入原组。5级终止，无进化金币费。

按钮有任一合法组时出现，无组隐藏；池收起按钮随之隐藏。成功后统一排序、取消选择、更新所有塔的可进化标识。`EvolvePool()` 返回实际产生的进化产物数，0代表未发生且给原因，不返回消耗宠物总数。

### G07：战场定向进化

选中塔 Level<5，战场与池中同种同级的已孵宠物合计≥3（包含主体）时，显示上方进化按钮和可升级标识。按主体Uid发起EvolveTower；锁定主体Species/Level/Uid/Pad，以池内同种同级Uid升序优先选最多2只材料，不足时再从其他塔按Uid升序补齐2只；不能取不同物种、不同等级、蛋或主体自身重复充数。

完整取得两材料后一次提交：删除两材料、主体Level加1、保留主体Uid与Pad，Cooldown=min(原Cooldown,新interval)，不增加金币消费。字段约定来自合同，不能改为强制清零CD。材料所在的战场Pad腾空；池材料被消费释放槽。进化后取消选择，信息面板消失；若还能进化则继续显示独立可升级标识，否则标识隐藏。本按钮每次只升主体1级。

失败不得先消耗一只材料。模型方法不负责屏幕位置：战场“右信息／下出售／上进化”、池“上信息／右下出售／右上进化”由HUD实现。

## 4. Formulas／公式

所有金币、计数、等级、波号均为整数；时间为秒。floor向下取整，Uid仅作稳定排序，不参与随机概率。

| 公式 | 变量、取值和例子 |
|---|---|
| ReadyWave=max(2,Wave+1) | Wave≥0；Wave0/1→2，Wave2→3；不是Wave+1后再按倒计时秒数孵化 |
| P(s)=1/M或0 | M=有效实际队伍长度1..5，成员均匀；非成员概率0 |
| SellValue=floor(sellBase×3^(L-1)) | sellBase=20，L=1..5；20、60、180、540、1620金币；蛋不适用，SellValue(蛋)返回0但Sell必须失败 |
| 等级L的1级当量=3^(L-1) | 1、3、9、27、81只；卖出总价值与材料卖价守恒 |
| 本组产物数=floor(n/3) | n为快照内同种同级数量；剩余原级=n mod 3；组总数变为n-2×floor(n/3) |
| 金币变化=击杀收入+清波收入+出售收入-50×成功抽取次数 | 初始500；部署、回收、进化增减为0；失败事务增减0 |

例：9只1级卖价合计180，进化得3只2级仍180；再进化1只3级仍180，没有合成卖出套利。购买3只指定物种至少支付150，合成2级卖60；首波赠宠是一次性来源，反复回收无法增加收入。

## 5. Edge Cases／边界情况

| 情形 | 结果 |
|---|---|
| Coins=49／50，池未满 | 前者失败且保持49；后者成功后0金币且多1蛋 |
| 池9格、只有50金币，快速连点 | 第一次成功到10格；第二次按现态失败，不产生第11格或负金币 |
| 池全为蛋 | 不可售、不可部署，不能进化；有未来波则提示开下一波，末波提示本局不能孵化 |
| 三同元素但不同物种 | 扩展情况下仍不可合；不能用元素替代Species比较 |
| 1个池材料+1个其他塔材料 | 两者均消耗，主体不动；2个池材料时其他塔必须保留 |
| 选中对象在批量进化中被消耗 | 取消选择及悬停详情，不引用已失效Uid |
| StartWave与DrawEgg同一输入批次 | 按UI提交顺序逐条原子执行；ReadyWave读取各自提交瞬间的Wave |
| 暂停中收起／展开动画尚未结束 | 冻结局内表现，隐藏战斗UI；恢复原折叠目标态，不额外抽取或合成 |
| 失效uid／pad超出0..13／不存在配置 | 返回失败和中文原因，不索引越界、不生成替代宠物 |

## 8. Acceptance Criteria／验收标准

执行 AC-G01～AC-G18。关键出口：Wave0蛋不会第1波孵化；末波蛋不凭空完成；失败经济事务无副作用；9合3不连跳；池优先材料和主体Uid／Pad／CD符合合同；收起界面不改变数据；所有成功移动只改变归属一次。数值示例为设计计算，不是运行测试通过声明。
