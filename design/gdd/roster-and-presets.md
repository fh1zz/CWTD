# 编队与预设系统

> v0.2变更：真实用户现要求“扭蛋直接孵出宠物，每宠共5阶段”。本篇保留v0.1原案追溯；当前即抽即用、35阶段数值／技能／图鉴和新增验收以 [v0.2设计](v02-direct-pets-five-stages.md) 为准，旧等待回合规则不再生效。

版本1.0｜Status: Draft｜来源：SRC-I12～I18；EXT-U；EXT-A。全文未由来源明确规定的细节均为 EXT-D。

## 1. Overview／概述

玩家按元素查看收藏宠物，选择最多5种不同物种作为本局的抽蛋池。三套局外预设减少反复编辑；关卡锁位以配置 slots 为准。进入编队只是建立草稿，实际出战或明确保存才提交对应数据。

## 2. Player Fantasy／玩家体验

玩家先确定想尝试的队伍，再在战斗中利用抽取和进化形成防线。已上阵标志、明确的技能说明与锁位提示，使“带谁”和“本局可能抽到谁”可预测；一次返回不会意外改坏常用队伍。

## 3. Detailed Rules／详细规则

### R01：收藏、界面与选择

`EXT-U`：首版收藏默认解锁金隼 falcon、木灵蛛 sprout、水獭 otter、火狐 fox、土龟 turtle、光鹿 deer、暗蝠 bat。每物种恰有一个元素，局外编队不允许重复物种，局内可以得到同物种多只实例。7物种均可直接选用，不设置局外稀有度、付费获取或属性养成门槛。

`SRC-I12～I15`：开始→选关→编队。元素页签展示元素图标与选中态；宠物列表显示头像、选中边框和“编队中”标志；本元素已上阵成员置顶，其他按稳定物种顺序排列。进入界面默认选择首个可见宠物；切换到无宠物的页签显示缺省说明，不保留失效选中对象。列表溢出支持滚动。首版各元素只有1种，仍保留这些状态约定。

右侧信息显示头像、元素、名称、攻击、间隔、范围、角色说明。`EXT-D`：首版宠物是固定炮台，不会被攻击，生命／防御不参与战斗，不显示虚假的0HP或可培养数值。技能区域展示本物种实际效果，可点击查看名称、效果、数值与单位；其他未定义技能槽不展示可点击假内容。点空白关闭技能说明，不误触上阵。

`SRC-I15` 的培养入口归入后续扩展；首版可隐藏，或禁用并标明“后续版本”，不能跳到空白界面。

### R02：编队初始化与锁位

主流程从以下来源选一个初始队伍：有合法已启用预设→该预设；否则有上次实际出战队伍→该队伍；首次启动均不存在→`EXT-D` 默认 [falcon,fox,otter,sprout,turtle]。

源队伍先去除未知ID、未解锁物种和重复项，保持剩余顺序，再取前 N 个，N=当前关卡 slots。后面未采用成员不进入本局抽蛋池。槽位总数5，前N个可编辑，余下锁定。教程N=3，其他两关N=5；不能硬编码“只取前3”，也不能截断后又自动补满。

有已启用但空的合法预设时仍使用该空预设，不偷偷换回上次队伍。非法预设索引按无启用处理；损坏资料的校验和修复见结算存档 GDD。

### R03：上阵、下阵与出战

选择未在队伍中的宠物，按钮显示“上阵”，加入第一个可用空位；没有空位时灰态说明“编队已满”。选择已在队伍中的宠物，按钮显示“下阵”，点击移除并紧凑排列剩余成员，不改变相对次序。点击下方已上阵头像可直接下阵。全部按钮具有默认、hover、按下和必要的禁用状态。

`SRC-I15 可选交互 + EXT-D首版要求`：点击操作是完整可用主流程；拖拽作为可替代方式，若后续实现，必须遵守空位直接放入、非空位替换并下阵旧成员、锁位拒绝的原图规则。拖动已在队伍中的成员视为移位／交换，不能复制物种。首版不把拖拽列为必需功能。

点击出战时读取草稿的有序非空成员：0只→按钮禁用且不创建GameModel；1..N-1只→显示“当前编队阵容未满，是否继续？”；取消保留草稿，确认才出战；N只→直接出战。弹框点击不能穿透，连续确认只创建一个战局。关卡和队伍最终校验成功后，才把真实队伍写为 lastActualTeam 并构造 GameModel；未满队伍不强制填充。

返回选关丢弃本次主流程草稿（上／下阵、换位均不保存），不更新 lastActualTeam；再次进入重新按 R02 优先级初始化。有启用预设时依然以预设优先，不能误用截图中无预设情形的“返回后使用上次阵容”覆盖预设规则。

### R04：三套预设

`SRC-I17～I18`：共3套，列表显示各成员头像；选中态与“已启用”标识分开，至多一套启用。进入预设页默认选中已启用项，否则第1套。点击列表只改变查看选择；点击“启用”才提交 enabledPresetIndex，立即刷新标识。

点击“编辑”创建该预设的独立草稿，下方仅“保存”按钮，没有出战。编辑使用5个可选槽，不继承当前教学关3槽限制；保存校验未知ID／重复／长度，成功后只覆盖该预设，返回列表。不保存返回则丢弃编辑草稿。允许保存或启用空预设，其出战安全由R03保证。保存未启用预设不会自动启用；保存已启用预设立即更新以后初始化来源，不改变已经启动的本局队伍。

`EXT-D（集成修订）`：打开预设管理时暂存主流程草稿。只查看或编辑预设而未切换启用项，返回恢复原草稿；明确改为启用另一套非空预设，返回按R02载入该预设。返回按钮与Esc一致。此规则避免仅查看预设就丢失当前编辑；它不改变从主编队返回选关时丢弃草稿的原案规则。

## 4. Formulas／公式

N=slots，为整数1..5；首版采用3或5。M=清洗、截断后的实际队伍长度，0≤M≤N。空槽数=N-M。模型只接受 M≥1。

本局单次抽中某物种概率 P(s)=1/M（s在实际队伍），否则0。不使用收藏总数7作为分母；不使用重复成员增加权重。

示例：预设 [falcon,fox,otter,sprout,deer] 进教程→[falcon,fox,otter]，每种1/3；进5槽关→原5种，每种1/5。配置测试N=4时应取前4，不能仍取3。空队伍不做除法计算。

## 5. Edge Cases／边界情况

| 情形 | 明确处理 |
|---|---|
| 连点上阵 | 提交后重新判断成员是否已存在；不生成重复成员 |
| 来源中有空槽或重复ID | 过滤空项及后出现的重复，保留首次出现顺序，再取前N |
| 取消不满确认 | 不更新上次实际出战，不关闭编队，不扣资源 |
| 主流程返回、预设编辑返回 | 各自只丢弃本地草稿，不回滚已单独确认的“启用”操作 |
| 编队选中宠物后切元素 | 选择对应页首个可见宠物，信息与按钮同步 |
| 新开一局和重新开始 | 前者取当前确认队伍；后者用当前战局的不可变队伍快照 |
| slots=0或大于5、收藏ID配置重复 | 属配置错误，禁用对应关卡并展示原因；不能进局自动猜值 |

## 7. Tuning Knobs／可调参数

| 参数 | 首版／安全范围 | 类型与影响 |
|---|---|---|
| LevelSpec.slots | 教程3，其余5；1..5 | Gate：影响选择复杂度与单物种概率 |
| 总槽数、预设套数 | 5、3；本版固定 | 合同：调整需同步UI与存档版本 |
| 默认队伍顺序 | falcon,fox,otter,sprout,turtle；必须合法不重复 | Gate：决定初次教学赠送的前三种 |
| 收藏解锁 | 全7种；本版固定 | 合同：不接入养成解锁 |

概率来自队伍长度，不设独立概率旋钮。

## 8. Acceptance Criteria／验收标准

执行用例 AC-R01～AC-R12，步骤与二值判据见 acceptance-cases.md。必须证明预设优先、前N截断、不重复、空队禁止、不满确认、返回不提交、保存与启用互相独立，且保存后的队伍与模型实际抽取池一致。拖拽属于可选交互，不作为首版完成的阻塞条件。
